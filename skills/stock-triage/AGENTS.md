# A 股全栈 Agent 系统 · AGENTS.md

> 项目宪法。任何 agent 在此项目目录下工作时，必须先读本文。

## 系统身份

这是一个 **A 股投资决策辅助系统**，不是交易机器人。它的职责是：
- 采集数据、分析信号、给出买卖建议
- **不自动下单、不操作账户、不代替人做最终决策**

## 绝对铁律（违反即事故）

### 1. 配置隔离
四个工具配置**绝不串改**：
```
OpenClaw → ~/.openclaw/
Claude Code → ~/.claude/
Codex → ~/.codex/
Hermes → ~/.hermes/
```
**改配置前必须确认目标工具。**

### 2. Cron 运行隔离
Hermes manifest 的 `command` **必须**走 `python scripts/hermes_job_runner.py <job-id>`，
真实业务命令放在 `run.command`，并写入 `$HERMES_HOME/cron/output/{job_id}/{run_id}.json` artifact。

如果 cron 由 Agent prompt 实现，主 cron agent 只能编排/汇总，数据采集和重计算必须委托子代理；
如果 cron 由仓库脚本实现，只能通过 `hermes_job_runner` 启动隔离子进程。

业务脚本内所有数据抓取必须用 Python `urllib`，禁止在 cron prompt 中直接使用 `terminal` 工具
（会触发安全审批锁，导致 cron 卡死）。

### 3. 全量扫描
用户说"全量"时必须真正穷尽，不能只扫预设板块。
参考：`sector_scan.py` 遍历所有行业板块。

### 4. 分析输出
当置信度为"高"或"中"时，个股分析必须包含：
- 具体买入价 / 止损位 / 目标位
- 持有周期
- S/A/B/C 分级 + 仓位建议

置信度为"低"或数据不足时，禁止输出方向性投资判断。

### 5. 网络故障处理
遇到 502 / DNS 劫持 / 连接拒绝等报错时：
- **先排查根因，修好，再汇报结果**
- 不要接连报错让用户处理
- 不要反复重试同一个失败端点（最多 2 次）

### 6. Cron 时间规则
- 不扎堆，时间分散错开
- 避免整点（如 08:30/08:55 而非 09:00）
- 新建 cron 前先 `cronjob(action='list')` 检查现有时间表

## 添加新功能的检查清单

1. **数据源是否在可用列表内？** → 不在则先验证端点
2. **是否需要新的 Python 依赖？** → 先 `pip install` 到 Hermes venv
3. **脚本是否 cron-safe？** → 只用 `urllib`，别用 `requests`（除非加载 `.env`）
4. **Manifest 是否隔离？** → `command` 走 `hermes_job_runner`，`run.command` 指向 canonical `skills/.../scripts/...`
5. **Cron 时间是否与现有冲突？** → 查 `cronjob list`，并跑 `validate_cron_manifest.py`
6. **是否需要更新 AGENTS.md？** → 数据源/铁律有变化必须更新
7. **输出是否控制在 Discord 一屏内？** → 配置 `max_output_chars`，例行任务 `deliver=local`
8. **无信号时是否静默？** → 高频 cron（盘中异动、资讯监控）必须静默

## 推荐审计铁律（REC-002 事故修复）

### 1. 每条推荐必须写入审计档案
每一条买入/卖出/加仓/减仓建议，必须同步写入 `data/recommendations.json`：
- 股票代码+名称
- 日期
- 建议操作 + 建议价格区间
- 推荐理由（简短的逻辑链）
- 风险提示（列出所有违反客观性铁律的预警）
- 结果（待验证/盈利/亏损）

不可事后补写，必须在**推荐发出时**同步写入。

### 2. 用户可以随时审计
用户说"你的推荐记录"、"审计"、"查一下你说的票"时，必须读取 `recommendations.json` 呈现给用户。

### 3. 推荐仓位计算（凯利公式 + 历史积累）

**原则：不拍概率，算赔率，靠积累。**

#### ① 赔率计算（每笔必算，数据可验证）

```
b = 预期盈利 ÷ 可能亏损

预期盈利 = 目标价 - 入场价
可能亏损 = 入场价 - 止损价
b > 1 → 赔率有利 | b < 1 → 赔率不利，谨慎
```

赔率是客观的，不需要拍脑袋，直接用价格算。

#### ② 历史胜率积累（替代拍概率）

建立 `data/trade_history.json`，每笔交易结束后记录：
- 股票代码、日期
- 策略类型（打板1进2/趋势低吸/洗盘捡筹）
- 是否到达目标（T）或止损（F）
- 盈亏金额

按策略类型分别统计胜率：
```
打板1进2胜率 = 打板1进2盈利次数 / 打板1进2总次数
趋势低吸胜率 = ...
洗盘捡筹胜率 = ...
```

#### ③ 凯利公式算仓位

```
f* = (bp - q) / b

b = 赔率（上述算出）
p = 该策略类型的历史胜率（从trade_history.json读取）
q = 1 - p
f* = 最优仓位比例（占总资产）

实际执行：取 1/4凯利 作为起始仓位
  1/4f* = 安全边际，防止单次大亏
  随着胜率数据积累（≥20笔），逐步提升到 1/2f*
```

#### ④ 启动阶段规则

当该策略类型的历史数据不足（<10笔）时，启用默认仓位：
- 打板1进2：3~5%总资产
- 趋势低吸：5~8%总资产
- 洗盘捡筹：4~6%总资产

目的是**收集数据，而不是赌对一次**。

#### ⑤ 输出格式

```
赔率：b = X.XX
历史胜率（打板1进2）：X% （N笔数据）
凯利仓位：f* = XX% → 执行1/4 = X%
推荐手数：X手（仓位X%）
最大亏损：XXX元
```

### 4. 禁入条件（违反则不可推荐）
以下任一条件满足，**禁止给出买入建议**：
- 空头排列（评分上限自动锁-0.5）
- 净利润同比下降 > 10%
- PE为负（亏损股）
- 布林跌破下轨（"加速下跌中，等待企稳"）
- RSI超卖但空头排列（"下跌中继，非洗盘"）

### 5. 评级自动降级规则
任何推荐必须经过"全量扫描"交叉验证后才能给出，不能仅凭单一板块或预设列表。

### 6. 全量扫描执行规程（用户强要求）
顺序不可颠倒：**先全量 → 再聚焦**。

```
第一步：sector_scan.py 遍历所有行业板块（ALL，不止预设的14个）
第二步：hot-money-tactics --rotation 看板块轮动（5日对比）
第三步：从全量结果中筛选强信号板块
第四步：对强信号板块做逐只个股技术分析
第五步：资金面/新闻面交叉验证
第六步：最终评级
```

禁止行为：
- ❌ 只扫"封测/AI算力/军工/电网/家电/煤炭"六个板块就号称全量
- ❌ 看到用户追踪的板块有信号就跳过其他板块
- ❌ 先有结论再找数据

允许行为：
- ✅ 全量扫描后发现用户追踪的板块确实是强信号，再深入
- ✅ 对非追踪板块也有好信号的，一并纳入候选

## 反身性分析框架（v2 — 含特殊买家维度）

> 基于索罗斯反身性理论 + A股资金结构特征的打板判断框架。
> 核心命题：打板本质是在反身性循环的繁荣期上车，但循环会被不同类型的资金扭曲。

### 1. 反身性基础模型

```
传统反身性循环：
  股价涨 → 更多人看到 → 资金买入 → 股价继续涨
   ↑_____________________________________↓
   （同质化资金，线性反馈）

修正后反身性循环（考虑资金结构）：
  股价涨 
   ├─ 游资看到 → 拉板吸筹 → 席位溢价 → 散户跟风 → 涨加速
   ├─ 量化看到 → 算法秒封 → 假封单 → 撤单 → 涨速扭曲
   ├─ 散户看到 → 追涨 → 轻度助涨
   └─ 机构/大股东看到 → 逢高减持 → 涨势打断
```

### 2. 四种关键买方的反身性行为特征

#### ① 游资（传统打板资金）— 反身性的启动器

| 特征 | 判断方法 |
|:----|:--------|
| 封板时间 | 非秒封，经历吸筹~拉板~封板的完整过程（30分~数小时） |
| 封单稳定性 | 封住后≥10分钟不撤单 |
| 席位效应 | 知名席位买入→吸引跟风盘→强化反身性 |
| 对反身性的贡献 | 最强。有"席位背书效应"，买=给散户信心 |

**游资主导的信号：** 低开高走涨停、午后封板、早盘洗盘后拉板

#### ② 量化机构 — 反身性的加速器和扭曲器

| 特征 | 判断方法 |
|:----|:--------|
| 封板速度 | **秒级封板**（竞价结束到封板<3秒）|
| 封单行为 | 封单量大但极不稳定，频繁撤单 |
| 竞价特征 | 第二天竞价量异常大（几十万手竞价单） |
| 对反身性的贡献 | 扭曲。加速涨速但制造假信号，涨停可能是"算法共识"而非"市场共识" |

**量化主导的信号：** 早盘秒板、封单忽大忽小、炸板后秒回封

**量化对打板的影响：**
- 繁荣期缩短（以前热3天，量化介入后热1天）
- 炸板率增高（量化撤单制造假封单，50%炸板率中有大量量化贡献）
- 第二天低开率增高（量化竞价砸盘）

#### ③ 机构/大股东 — 反身性的打断器

| 特征 | 判断方法 |
|:----|:--------|
| 卖出方式 | 大宗交易、集合竞价砸盘、被动减持公告 |
| 触发条件 | 股价涨到一定程度→解套/达到减持价 |
| 对反身性的贡献 | **打断循环。** 不管多少买盘在涌入，大股东减持公告可以一刀切断反馈 |

**机构卖出信号：** 近期有减持公告、大宗交易折价率大、龙虎榜出现机构专用席位卖出

#### ④ 潜伏盘 — 反身性的反向力量

| 特征 | 判断方法 |
|:----|:--------|
| 来源 | 长期横盘期的老股东、定增解禁、员工持股解禁 |
| 卖点 | 涨停→解套→卖 |
| 对反身性的贡献 | 涨停初期制造抛压，封单质量下降 |

### 3. 反身性检查四步法

任何打板推荐前，必须完成以下检查（写入审计文件）：

**第一步：反馈方向判断**
- 向上加速（涨停数递增、连板高度在增加）→ 繁荣期 ✅
- 趋平（涨停数不变、高度不突破）→ 平台期 ⚠️
- 向下反转（涨停数减少、高度压缩）→ 衰退期 ❌

**第二步：资金结构判断**
- 涨停是秒封→量化主导 ⚠️ 反身性不可靠
- 涨停是慢拉→游资主导 ✅ 反身性相对可靠
- 近期有减持公告→打断风险 ⚠️
- 前高附近大量套牢盘→抛压大 ⚠️

**第三步：催化强度判断**
- 有实质催化（政策/财报/行业数据）→ 反身性有支撑
- 纯情绪驱动（无实质消息）→ 反身性脆弱

**第四步：综合评级**

| 资金结构 | 反馈方向 | 催化 | 可操作性 |
|:--------|:--------|:----|:--------|
| 游资主导 | 向上加速 | 有实质催化 | ✅ 最可靠 |
| 游资+量化混合 | 向上加速 | 有催化 | ⚠️ 参与但控仓位 |
| 量化主导 | 秒板 | 无实质催化 | ❌ 放弃 |
| 任何结构 | 衰退期 | 任何 | ❌ 放弃 |
| 前高附近+减持 | 向上 | 任何 | ⚠️ 只做1进2，不恋战 |

### 4. 量化参与度速查表

| 观察指标 | 量化主导 | 游资主导 | 混合 |
|:--------|:-------:|:-------:|:----:|
| 封板速度 | <3秒 | >30分钟 | 3秒~30分 |
| 封单稳定性 | 频繁撤单 | 稳定≥10分钟 | 偶尔撤单 |
| 炸板率 | >50% | <30% | 30~50% |
| 竞价次日量 | 异常大 | 正常 | 中等 |
| 建议态度 | ❌放弃 | ✅参与 | ⚠️谨慎 |

### 5. 反身性与禁入条件的联动

| 禁入条件 | 反身性解释 |
|:---------|:----------|
| 空头排列不推荐 | 空头=反身性向下循环未结束，低PE+下跌=价值陷阱 |
| 净利润降>10%不推荐 | 盈利下降→估值变便宜→继续跌→PE更便宜，这是反身性陷阱的经典形态 |
